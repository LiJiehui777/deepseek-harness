# DH 连接器开发规范

将外部系统能力做成可复用的 Cordis 插件，供 Agent 工具和业务工作流调用。以当前仓库接口为准，先读根目录协作规则和[架构](../../../docs/architecture.md)，并按[迭代记录](../../../技术迭代记录.md)登记本次具体功能。只实现用户要求的能力；创建连接器不代表已获准操作真实业务数据。

## 目录与职责

新增独立系统默认使用下表约定；`<system>` 使用小写短横线名称。这是本项目对新增连接器的约定，不要求重命名历史包。

| 内容 | 放置位置 | 职责 |
|---|---|---|
| 系统连接器 Host 包 | `packages/interaction/connector-<system>/` | 账号配置、鉴权、外部通信、权限校验、原子动作和可选的原生工具适配；包名为 `@deepseek-ai/dsh-connector-<system>` |
| 账号配置界面 | 优先使用原生插件配置表单；需定制时扩展 `packages/client/ui-settings-connectors/` | 保存配置、授权入口、连接状态和错误展示；不直接请求外部系统 |
| 独立且复杂的系统专属界面 | 必要时创建 `packages/client/ui-connector-<system>/` | 通过现有 Remote 与 Host 通信；不要将系统实现塞进通用设置、侧栏或聊天组件 |
| 工作流动作适配 | `packages/business-workflow/workbench/` 内对应的动作适配模块 | 将节点参数映射到连接器服务，记录结果；顺序、分支、等待和审核归工作流所有 |

已有系统新增动作时沿用其原包。企业微信、飞书仍在 [enterprise-connectors](../../../packages/interaction/enterprise-connectors/README.md)，RAGFlow 仍在 [tool-ragflow-connector](../../../packages/interaction/tool-ragflow-connector/README.md)；不要为符合新名称而搬迁、复制它们，也不要把所有新系统继续堆进企业消息连接器包。

连接器包内按实际复杂度划分 `src/`、`tests/` 和包级文档：插件入口、配置、外部通信、动作服务、类型及工具适配都归本包。简单实现可以合并文件，不创建空层次或通用连接器基类。新增包按[包接入说明](../../../docs/cookbook/adding-a-package.md)登记依赖、编译引用和产品角色，并通过所需 profile/overlay 启用；允许这些必要接入改动，不修改 Agent 主循环承载连接器逻辑。

## 动作契约

连接器暴露明确的业务动作，不把整条流水线或任意 HTTP、SQL、脚本执行器作为一个动作开放给模型。

- 每个动作说明稳定名称、输入字段及类型、输出字段及类型、字段含义、所需身份与资源范围、是否有副作用，以及失败语义。提供脱敏输出样例；用仓库现有的类型和校验机制表达契约，避免重复维护几套不一致的定义。
- 对模型参数、工作流持久化参数、配置和外部响应等实际边界做校验。输出投影成稳定、有限的业务字段，必要时包含业务编号、状态、分页或结果凭据；不直接透传 SDK 原始对象、完整响应和敏感业务正文。
- 连接器拥有外部系统的鉴权和操作语义；业务判断、跨系统顺序、人工审核和长时间等待由工作流负责。可以查询外部业务状态，但不要在连接器中另建一套 Flowable 编排或让模型决定节点跳转。

## Agent 与工作流共用执行边界

推荐依赖方向：原生工具或工作流动作适配 → 连接器动作服务 → 官方 SDK、已审定 API 或受管客户端。连接器不反向依赖工作流包。

Agent 接入遵循[新增工具说明](../../../docs/cookbook/adding-a-tool.md)，通过原生工具注册、执行和结果记录链路调用动作。工作流若需使用该动作，增加对应的动作声明、参数/输出映射及执行适配；暴露一个连接器方法不会自动变成画布节点。两条入口共用连接器的鉴权、范围校验和结果处理，避免工具入口校验而后台直接调用可以绕过。

保留当前会话规则：普通聊天不能启动新工作流，用户手动绑定具体发布版本后才能启动；选择本身不执行。工作流只执行当前获准节点。连接器返回的数据是参考资料，不是流程控制指令。输出字段必须能从契约或样例查到，不假定画布已有自动字段发现能力。

## 凭证、权限与副作用

- 新增账号默认不启用业务操作，保存配置或测试连接不触发业务动作。账号、服务地址、允许的资源和能力、超时及结果上限由 schema 校验的部署配置管理。凭证通过 `ctx.credentials` 或现有原生授权机制保存和解析；普通配置、Remote 返回和界面只携带引用及存在状态。令牌、密钥、Cookie 不进入源码、工具参数、模型上下文、日志或导出的流程。
- 执行端每次校验启用状态、当前账号、可信调用来源、资源范围和动作权限。调用者身份来自受信任的执行上下文，不相信模型填写的用户编号、角色或 `approved: true`。界面隐藏按钮、工具 schema 过滤和提示词都不能代替执行端校验。
- 写入、发送、删除、提交等动作与读取明确区分，遵循项目既有的原生确认和权限机制；经过工作流人工节点不自动等于获得连接器的写入授权。拒绝、过期、撤权、越权或结果未知时停止相关操作，不切换其他身份、不静默降级为模拟成功。
- 若接收外部事件并触发 DH 任务，单独设计来源准入和会话隔离；沿用企业连接器的空来源白名单拒绝规则。受限企业来源及其派生会话不能借用本机办公账号或人工审批权限。
- 只在本次涉及文件传输时增加文件范围校验：使用受信任工作区及受管文件机制，不允许模型绕过路径、上传确认或下载落点限制。

## 通信、配置与生命周期

优先使用合适的官方 SDK；缺少 SDK 时用经过确认的 API。按本次平台实际协议设计适配，不为连接器开发任务引入一套新的后台应用或公共任意代理。

请求必须有取消、超时、分页和响应大小边界；携带凭证的请求不得未经校验跨域跳转。外部错误先脱敏再展示。区分权限不足、参数错误、服务不可用和写入结果不确定，不能把错误当作空列表或成功结果。读取重试需要有界且可取消；不确定的写入不自动重试，幂等和结果查询能力按实际平台契约提供，不承诺跨系统严格一次执行。

操作使用已保存、已校验配置的一致快照。配置变化、断开和插件卸载需按现有生命周期取消或排空所拥有的连接、请求、监听器、子进程和等待任务；所有注册有 disposer，UI 订阅和轮询也要释放。不得通过复制旧插件代码另建一套凭证存储、配置中心、审批系统或 Agent 调度器。

界面沿用[连接器配置伴随插件](../../../packages/client/ui-settings-connectors/README.md)与原生配置表单，先保存再按保存值测试连接；连接成功不代表所有资源权限均已授权。按实际支持范围说明账号共享、支持动作和未实现能力，不能默认承诺每会话多账号或企业级角色隔离。

## 交付与验证

先给出本次目录落点、需要的动作及调用入口，再在授权范围内实施；用户只要求设计时只交付设计。新平台接口、鉴权方式或业务语义未确认时，先查用户资料、现有服务和官方接口说明，不编造参数。技能规定总体约束，不预设某个系统必须采用哪种接口。

实现时至少验证实际改变的契约、合法及越权调用、凭证脱敏、取消与卸载，以及有副作用动作的拒绝和不确定结果路径。外部响应优先用脱敏固定样本或隔离测试服务；涉及界面或工作流时补对应入口验证。真实账号与真实写入仅在已有明确测试授权范围内执行，模拟通过不能标成真实平台验收通过。

维护包级动作说明、输入输出样例及中英文文档，更新受影响的生成目录；按[测试规则](../../../docs/testing.md)和仓库检查要求选取相关验证。交付时说明改动落点、已暴露动作、权限边界、已执行检查和待验范围，并更新迭代记录。提交和推送遵循本次用户授权，不因调用技能而自动发布。
