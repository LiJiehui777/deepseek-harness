# Agent Note：对话授权的渠道读取插件

Status: implemented

[English](2026-10-08-conversation-channel-readers.md) | 中文

## 问题

聊天渠道凭证可以连接机器人，但不会注册模型工具，也不会授予全部历史消息的权限。多个对话共用不受限制的机器人身份，还会使记录归属不明确。

## 决策

可选的[聊天记录插件包](../../../../packages/interaction/tool-chat-records/README.zh.md)通过原生插件命令安装。空的配置补丁不会授予进程全局工具；飞书和企业微信独立实例由已授权的对话预设挂载。宿主签发的令牌标识已保存对话及其所有者。宿主每次读取都解析当前账号绑定和权限，因此改变工具参数不能扩大账号访问范围，关闭保存会撤销后续读取权限。

平台凭证保存在 RAGFlow。飞书使用官方应用权限读取机器人可见历史。企业微信在主动开启后保存接收文字消息，与普通聊天助手回复独立；完整企业会话存档需要单独接入。已持久化的工具文本支持标准 Web 检查视图。

## 考虑的替代方案

将应用密钥复制到模型参数或浏览器设置会暴露授权。将接收回调当作完整历史会误述平台权限。全局工具会向无关对话授予访问权限。

## 影响

每个对话为每个启用的平台选择一个账号。只读工具提供稳定定义、受大小限制的分页、取消和超时。Loader 组合快照固定工具定义和可见记录；卸载一个配置行会移除它的两个工具。通过正式 headless 配置运行的无密钥会话回放执行四个只读工具，并在持久化历史中保留完整结果。

宿主返回插件通过 `settings.plugins.tab` 在原生「设置 → 插件」贡献「聊天服务」标签页。账号元数据仅通过验证父窗口与来源的桥接传递，凭据留在宿主。管理任一账号会以浮层打开已有宿主表单，保留 iframe、原生 Session 和未发送草稿。新建对话时另行选择本次启用的插件及账号。
