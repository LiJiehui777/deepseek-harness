# Agent Note: 会话启动工作流前必须手动选择

Status: implemented

[English](2026-11-03-manual-workflow-selection.md) | 中文

## 问题

会话选择器将未绑定的 Session 标为普通聊天，但保留启动能力会使 agent 根据对话请求启动工作流。用户需要通过手动选择，区分讨论工作流与授权使用它。

## 决策

会话必须持有用户选定的已发布工作流及版本，agent 才能启动实例。这替代了 [Flowable 集成](2026-11-02-flowable-business-execution.zh.md)中允许未绑定启动的行为。普通聊天保留发现能力以推荐流程，以及查询和终止已有归属实例的能力。它隐藏启动工具定义，并接收已记录的指令，要求提示用户手动选择。注册表检查拒绝隐藏的启动调用；工具执行器独立要求确切的选择，串行启动接受操作再次校验。

选择器仍是经过认证的显式界面操作，选择本身不启动执行。选择操作及工作台的两个启动入口拒绝带 agent 发起身份的调用，避免替代服务调用自行选择，或通过操作员启动入口绕过会话规则。工作台中有意发起的测试仍属于操作员操作。普通聊天的其他工具保留原有权限。

清除绑定会阻止后续会话启动，不会取消已接受的引擎实例或改变审核权限。现有[会话等待机制](2026-11-03-conversation-workflow-waiting.zh.md)继续跟进已接受的实例。不需要修改存储格式或 agent loop。

## 考虑过的替代方案

**仅用提示词建议选择。** 模型仍然可以调用可见或已知的启动工具。接受操作负责执行这条规则。

**禁用普通聊天的所有工具。** 用户要求区分的是启动业务工作流；无关的会话能力仍然有用。

## 影响

用户先选择工作流，再请求执行。普通聊天可推荐已发布流程，并引导用户使用选择器。界面文案及模型可见快照描述该行为。执行器测试证明，即使没有提示词策略，缺少选择及版本不匹配也不会触发启动。构建后的浏览器场景验证普通聊天请求不产生引擎实例、直接和替代入口被拒绝、手动绑定后成功运行至审核及完成，以及切回普通聊天后拒绝启动。
