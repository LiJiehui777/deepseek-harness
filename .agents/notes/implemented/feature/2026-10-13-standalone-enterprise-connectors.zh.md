# Agent Note: 独立企业连接器

Status: implemented

[English](2026-10-13-standalone-enterprise-connectors.md) | 中文

## Problem

独立 DH 同时需要平台资源工具和远程任务入口。融合版飞书及聊天记录插件依赖 RAGFlow 宿主桥接，单独安装无法完成平台授权或接收消息。

## Decision

飞书资源读取明确选择应用或用户身份。设置卡片使用互斥单选项，仅显示所选身份的配置说明。个人授权及回调设置仅在用户身份下出现，两种身份都保留应用凭证。身份切换在保存前仅暂存，并保留已有用户授权及机器人设置。原生授权服务负责取消授权尝试；同一浏览器 cookie、一次性 state 和 PKCE 将确认流程绑定到发起的 DH 浏览器和已保存账号。仅宿主可访问的凭证记录保存用户令牌及授权权限，原子读改写负责跨进程串行轮换刷新令牌。用户授权缺失或权限不足时读取会失败，不会换用应用令牌。机器人传输和发送保留应用身份。授权由同一个 DH 主目录共享，包括已获准的远程任务，不提供按个人隔离身份。解除授权删除本地凭证，平台侧的授权关系仍由飞书管理。

可选原生插件包使用飞书和企微官方 SDK。独立设置卡片管理能力开关及发送者、会话范围，DH 凭据服务管理密钥。长连接不需要公网入站服务。两个账号默认关闭；发送者名单为空时拒绝全部任务。未授权文本不保留，但状态提供发送者和会话 ID 供明确配置。模型主动发送要求开启发送、明确目标和原生单次确认。

远程输入通过公开 SessionController 提示管线进入对话，请求 ID 派生自平台消息。按发送者隔离的会话保留原生持久化、预设、工具和审批。连接器管理 SDK 连接、有界入站队列及从消息入账到整个 Agent 空闲的回复观察器。重新配置取消自己的观察器，不接管 Agent 生命周期。回复选择这段区间内最后一段助手文本，因此本地后续消息也可能影响回复，不保证逐条消息的因果归属。

飞书应用权限和资源共享决定聊天历史及 Docx/Wiki 读取范围。企微智能机器人的读取只展示当前进程收到的有界消息缓存，重连会清空缓存。完整工具结果有大小上限，HTTP 读取拒绝重定向并遵循取消信号。平台错误只返回脱敏提示，交付结果不确定时不自动重试。

## Alternatives considered

宿主桥接保留对融合版 RAGFlow 的依赖。飞书 OpenAPI MCP 提供更广泛的工具和 OAuth，却不能取代双向即时通讯传输。官方企微 OpenClaw 适配面向另一套插件 API。社区 dsh-connect 提供飞书消息及更丰富的即时通讯控制，但未覆盖本次两种平台及原生设置卡片。复用官方传输避免自行维护认证与重连协议，同时保留当前仓库的 SessionController 路径。

## Consequences

真实 Loader 测试覆盖认证、范围、密钥脱敏、结果上限、凭据轮换和卸载。完整构建的 Web 场景配置两个账号，通过本地平台夹具驱动官方 SDK 长连接；远程任务使用确定性的外部模型读取飞书文档，在模拟人工确认后通过两个平台发送，并持久化原生对话入账。设置 ARIA 和工具 schema 固定公开输出。真实 Web OAuth 夹具验证浏览器绑定、一次性回调、用户令牌读取、原子续期和解除本地授权。真实账号权限和交付仍需配置凭据验证。目前没有多维表格及日历操作、会话存档、媒体或即时通讯侧审批。配置和限制见[用户指南](../../../../docs/user/enterprise-connectors.zh.md)。
