# Agent Note: 可选 ACP 实时助手更新

Status: implemented

[English](2026-09-15-opt-in-acp-live-assistant-updates.md) | 中文

## 问题

ACP 从已提交的 `assistant/message` 事件投影助手文本与推理。因此，即使 Agent 在运行时发布有序的 `agent/assistant-stream` 增量，交互式客户端仍要等待完整模型尝试结束。提交后再模拟打字既不能降低延迟，也会把缓冲输出错误地呈现为模型流式生成。

## 决策

ACP 插件提供默认值为 `false` 的 `liveAssistantUpdates`。启用后，会话将其确切归属 Agent 发出的非空 `text-delta` 与 `reasoning-delta` 帧映射为标准 `agent_message_chunk` 和 `agent_thought_chunk` 更新。现有按会话输出链会把实时增量与工具、配置、已提交内容及用量更新串行化，提示词仍在该链交付完成后才结算。

会话记录每个轮次与步骤是否已向客户端发送文本或推理。其已提交 `assistant/message` 投影只省略对应内容块，图片与用量仍在提交时发送。持久失败尝试会清除抑制状态，避免丢失后续已提交输出。标准 ACP 没有撤回已发送消息前缀的操作，因此被放弃或重试的尝试内容仍是临时内容；无法接受此呈现取舍的部署继续使用默认的仅提交模式。

RAGFlow 通过 ACP profile 覆盖启用该选项，因为它面向人的聊天客户端需要真实的模型生成时延，并在运行完成前将实时输出视为临时内容。该选项只改变传输时序，不添加 DSH 呈现类型或模型可见内容。

## 考虑过的替代方案

**收到已提交输出后模拟打字。** 拒绝，因为用户仍需等待完整模型调用，而且动画会错误暗示上游具有增量输出。

**默认让 ACP 发送实时增量。** 拒绝，因为自动化客户端可能把每次更新都解析成已提交输出，而标准 ACP 无法撤回失败尝试的前缀。

**增加 RAGFlow 私有流协议。** 拒绝，因为标准 ACP 已能表示文本与 thought chunk，第二套提示词传输还会重复会话、取消、工具和权限生命周期。

## 后果

交互式 ACP 部署可以按提供方生成速度呈现文本与推理，现有客户端则保留仅提交行为。实时交付放弃了对已放弃尝试的回滚，因此需要按临时内容呈现。聚焦的 ACP 投影与提示词测试固定逐增量交付、已提交块抑制、默认行为、输出顺序和提示词结算。
