# Agent Note：独立 RAGFlow 连接器

Status: implemented

[English](2026-10-09-standalone-ragflow-connector.md) | 中文

## 问题

内嵌 DH 运行时由 RAGFlow 宿主管理启动、模型和会话绑定。独立 DH 应用需要可选的知识访问，同时保留自己的模型、插件和会话生命周期。

## 决定

增强版目录提供独立的数据目录和 Web 启动入口。RAGFlow 连接器是调用公开 REST API 的原生工具插件，向 DH 插件页面注册实时设置和卡片。DH 凭证服务保存 API Key，部署配置的知识库范围限制检索和返回片段。空选择只允许列出知识库。连接故障作为工具错误返回，不阻断 DH 启动和普通对话。

直接 REST 路径支持知识库发现和带引用检索，无需 Gateway 或 MCP 部署。DH 是应用的所有者。飞书、企业微信需要独立的授权提供方，仅安装原有宿主管理的渠道桥接包不会获得独立连接能力。

## 考虑过的替代方案

将 DH 嵌入 RAGFlow 会保留宿主控制，无法独立启动。把知识复制到 DH 会重复索引和访问策略。复用会话桥接令牌仍依赖融合版 Gateway。公开 API 保留 RAGFlow 独立部署方式，其 API Key 权限继续作为授权依据。

## 后果

原生 Loader 组合测试访问真实本地 HTTP 模拟服务，固定工具模式和引用结果，并检查卸载。其他测试覆盖范围拒绝、关闭状态、凭证轮换、响应限制、重定向及无效提供方响应。客户端测试检查原生卡片和凭证写入。一个本地数据目录共享一套连接及知识库范围；按对话绑定和独立渠道授权留待后续。[用户说明](../../../../docs/user/ragflow-connector.zh.md)记录已提供的控制项。
