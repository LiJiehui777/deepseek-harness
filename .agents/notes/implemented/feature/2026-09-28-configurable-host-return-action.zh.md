# Agent Note：可配置的宿主返回操作

Status: implemented

[English](2026-09-28-configurable-host-return-action.md) | 中文

## 问题

应用可以启动原生 DeepSeek Harness Web 并把浏览器交给它，但组装后的页面没有产品拥有的返回入口。认证重定向会让浏览器历史不稳定，而且历史按钮也无法表达 Harness 只是更大宿主流程中的一个界面。

## 决定

新增双端 Web 插件 `@deepseek-ai/dsh-client-ui-host-return`，注册到根作用域 `sidebar.brand.action` 席位。Web bundle 挂载该包但不提供配置，因此默认不渲染。嵌入方覆盖层可以提供绝对 HTTP(S) `returnUrl` 和只用于显示的 `hostName`；Host 端通过结构化 `webserver/index-inject` 全局数据行投射校验后的值，浏览器端随后在展开侧边栏的智能体身份前渲染本地化图标。链接以顶层浏览器上下文为目标，因此宿主会替换整个嵌入式工作台，而不是只在 iframe 内导航。

之所以需要显式启动投射，是因为静态客户端清单只按包名组装浏览器 Loader 行；Host Loader 行配置不会自动复制到这些浏览器行。浏览器会重新校验投射值，而不是直接信任页面全局数据。

客户端拒绝缺失、过长、相对、含凭据以及非 HTTP(S) 的目标。这是纵深防御而不是授权边界：嵌入应用拥有 Loader 行配置，必须在地址到达浏览器之前完成授权。

RAGFlow 在每个 Agent 的 Web 覆盖层中提供当前站点的 `/agents` 地址。因此集成不依赖开发端口和部署主机名，也不会返回 Agent 详情路由后立刻再次启动 Harness。

## 考虑过的替代方案

**依赖浏览器后退。** 认证重定向使历史链条不固定，而且不了解集成边界的用户看不到这个动作。

**写死 RAGFlow 开发地址。** 只能适用于一个主机名和端口，在局域网、HTTPS、代理和其他本地配置下都会失效。

**把操作放在侧边栏页脚。** 返回入口仍然可见，但会让宿主导航与智能体身份分离，并持续占用纵向空间。专用且可选的品牌行席位既保持外壳通用，也把嵌入操作放在其所管理的身份旁边。

## 结果

独立 Harness Web 保持不变，因为没有 URL 时既不会贡献启动值，也不会贡献插槽项。嵌入式部署可在工作台自身界面中获得明确出口，因此宿主不再需要重复的顶部栏。侧边栏收起时，返回按钮会随品牌行隐藏；用户展开轨道后即可重新看到。目标地址变化时需要重启 Web 进程，因为 Host 值会被采样进每份认证启动文档。
